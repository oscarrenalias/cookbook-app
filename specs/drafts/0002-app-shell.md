# App Shell with Settings Entry Point

## Objective

Establish the navigation skeleton — a three-tab interface (Recipes, Meal
Plans, Shopping Lists) with a Settings sheet — so subsequent feature specs
have a stable home to attach screens to.

## Acceptance Criteria

- Launching the app shows a `TabView` with exactly three tabs:
  - "Recipes" with SF Symbol `book.closed`
  - "Meal Plans" with SF Symbol `calendar`
  - "Shopping Lists" with SF Symbol `cart`
- Each tab, when selected, displays an empty-state view containing an icon,
  a title matching the tab name, and a one-line subtitle indicating the tab
  has no configured content yet (e.g., "No recipes folder selected.").
- The Recipes tab is wrapped in a `NavigationStack` with navigation title
  "Recipes" and a trailing-toolbar gear icon button.
- Tapping the gear icon presents a modal sheet whose navigation title is
  "Settings" and whose body contains a `Form` with a single section labeled
  "Recipes folder" holding a disabled row "Not configured".
- The Settings sheet has a "Done" button that dismisses it.
- A unit test verifies that `AppRoot` exposes three tab labels in the order
  above, and that `SettingsView` can be instantiated without crashing.
- `xcodebuild test` (the project's configured `test_command`) passes after
  the changes.
- `project.yml` is regenerated via `xcodegen generate` if the source layout
  changes require it; the resulting `.xcodeproj` is not committed (already
  gitignored).

## Scope

**In scope:**
- Tab navigation shell (SwiftUI `TabView`).
- Reusable empty-state view component.
- Settings sheet scaffold with placeholder content only.
- Replacing the current placeholder `ContentView`.

**Out of scope (each is a follow-up spec):**
- `UIDocumentPicker` integration and the actual folder-selection flow.
- Security-scoped bookmark persistence and resolution on launch.
- Any CookLang parsing or recipe data layer.
- Recipe rendering, list views, thumbnails, search.
- Meal plan creation, editing, or persistence.
- Shopping list creation, editing, or persistence.
- iPad-specific layouts (default size-class behavior is acceptable for v1).

## Notes for the developer agent

- The `.xcodeproj` is generated by `xcodegen` from `project.yml`. After
  adding new Swift files, run `xcodegen generate` from the repo root before
  running tests, otherwise `xcodebuild` will not see the new sources.
- Do not hand-edit `CookbookApp.xcodeproj/`. It is gitignored and
  regenerated.
- Decisions for folder access, parser, thumbnails, and the settings surface
  are documented in `docs/architecture.md`. Read it before designing new
  modules.
- Tests use the Swift Testing framework (`import Testing`, `@Test`, `#expect`)
  rather than XCTest.
